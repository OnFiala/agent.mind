# agent.mind 1.3.0 candidate

This release completes the practical Python source workflow and includes the
post-1.2.1 repairs merged in [PR #15](https://github.com/OnFiala/agent.mind/pull/15).
[GitHub Releases](https://github.com/OnFiala/agent.mind/releases) owns publication
and downloadable bytes. Source preparation and a passing check do not establish
publication or upgrade any existing project. The rollback version is **1.2.1**.

## Scope and contract

Python now exposes named declarations, source-module references and conservative
bare same-file call/construct relations. Source spelling, stable symbol IDs,
UTF-16 ranges, hashes and parser provenance remain available. Lexical binding keys
and import module identifiers use Python's NFKC normalization; filesystem names
and displayed source identifiers are not rewritten.

Supported complete Python input can return `current` and pass the existing strict
preflight. There is no unconditional language-level warning. Normal unresolved
relationships are informational, as in JavaScript. Read/parse errors, known
malformed or unsupported syntax, incomplete scans and budget failures still produce
`partial` and fail preflight. Revision and binding checks are unchanged.

The analyzer uses the existing Lezer dependency and synchronously consumes checked
text. It does not read the filesystem, run Python, import target modules or inspect
the environment. The index resolves absolute imports only from the project root
and explicit relative imports within an indexed regular-package ancestor.
Internal namespace subdirectories are traversed only below that known anchor;
a namespace without a source file creates no file edge. Intermediate module
collisions, missing explicit relative modules and ascent beyond the anchor remain
blocking diagnostics. Missing absolute
modules are external/unresolved source references, not verified installed packages.
`from package import member` refers to the base module; attribute/submodule
ambiguity does not create a guessed member-file edge. Python external references
never inherit JavaScript security labels. Python test naming/reference links remain
separate from actual test execution and coverage.

Bare call targets require one unmodified same-file binding. Parameters, whole-body
local bindings, closures, class namespace boundaries, writes, decorators and
ambiguous declarations suppress uncertain targets. Types, imported/member calls,
dynamic dispatch, annotation evaluation, comprehension/lambda bodies, runtime
import paths, top-level or merged namespace packages and implicit src layouts remain outside the
inferred call/module model. These limits are explicit in context. `current` is
fresh bounded analysis, never a CPython-validity or runtime-correctness claim.

Existing parser/file/declaration/node/depth budgets remain; calls are additionally
bounded to 10,000 sites and 5,000 edges per file. Limits are not CPU/RSS/time
sandboxes. TypeScript/TSX/JSX remain the separate syntax-only partial pilot.
There is no new parser dependency, process, plugin, persistent service, target
manifest or global configuration. Existing JS repair behavior remains covered.

## Upgrade and rollback

Use the existing [update procedure](../../README.md#update-from-an-older-version).
Save the owner's map outside the project, stop the owned foreground view, uninstall
through the installed CLI and inspect its result. Park preserved remnants outside
the source project; do not purge, overwrite user files or remove recovery copies.
Install the selected verified release, restore the map, inspect status/context and
reload the coding host's project instructions.

Rollback uses the original published 1.2.1 archive, restoring its declaration-only
Python behavior and rejecting Python preflight. Existing targets retain their
version pins until an explicitly authorized upgrade.

PR #15 is an independent earlier repair. No source rollback silently changes an
installed target. The upgrade harness retains old-release verifiers and ownership,
recovery, source bytes, user map and stale-binding checks in both directions.
