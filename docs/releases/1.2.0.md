## Change from 1.1.0

Python `.py` files gain named function, async-function, class and method declarations,
source locations, hashes and parser provenance. Version 1.1.0 only inventories and
reads those files. This is the bounded L5 pilot merged in
[PR #8](https://github.com/OnFiala/agent.mind/pull/8), whose reviewed implementation
is `ee0a97434788dd265a7dac885253368eed66b489`, merged as `f764fa9c`.

This preparation changes the version/description, usage documentation and release
checks. Runtime modules, UI and parser dependencies are unchanged from that merge.
Lezer Python 1.1.19 and three supporting MIT packages are bundled inside the
integration. No Python interpreter, target imports, install scripts or build
configuration execute. Node >=22, macOS/Linux and loopback-only viewing remain.

## Scope and limits

Every Python file is `partial`; strict preflight rejects it. Python import/name,
call/type/security and framework relationships are not inferred. Lezer is an editor
grammar, not CPython validation. A recovery-free tree does not prove valid Python;
unsupported syntax and omissions remain explicit. `.pyi` and notebooks remain
inventory-only. The 64 KiB input cap and 2,000-symbol / 100,000-node / depth-256
traversal limits are not parser deadlines or a sandbox. The
[fixed Python contract](../reviews/2026-11-01-python-pilot.md) records exact grammar
limits, source-range rules and prior measured acceptance evidence.

The JavaScript and typed-source capabilities retain their existing limits. This
release does not establish general framework, Windows/WSL, remote-host or complete
editing-workflow support.

## Upgrade and rollback

Follow [Update from an older version](../../README.md#update-from-an-older-version).
Save the user map outside the project and retain the original verified release.
Stop the view, uninstall using the currently installed CLI, require successful
`state: "uninstalled"`, and park the preserved directory at a unique path outside
project inventory. Install the selected new release into a fresh integration,
restore the map, inspect status/context and reload the host's project instructions.
Preserve edited/unknown files and recovery copies; no purge or in-place overwrite
is part of the upgrade.

Rollback repeats that sequence using the original 1.1.0 release and saved map.
Python returns to inventory/text-only inspection; the source is unchanged. A new
installation has a new binding, so previous context/preflight receipts expire.
Preserved post-uninstall files are recovery data, not a runnable old installation.
If the candidate is rejected after uninstall, reinstall the original verified
release and restore the map; do not force installation over partial state.
