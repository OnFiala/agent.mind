# agent.mind 1.3.1 candidate

This patch repairs incorrect Python dependency evidence and its shared canvas/context
projection. It includes the private binding/import identity repair merged in
[PR #17](https://github.com/OnFiala/agent.mind/pull/17) as
`0905300998d9d26b79833eda73e077f6732a85c5` on 2026-11-03, plus three subsequent
correctness fixes. [GitHub Releases](https://github.com/OnFiala/agent.mind/releases)
owns publication; this candidate is not a published archive. Existing installations
retain their pinned version. ROADMAP owns live status.

## Behavior and boundaries

- File-body and function constructions retain `construct` / `constructs` through
  `partCanvas`, collapsed areas and expanded areas. Their original source edge IDs
  and evidence remain available, including internal area references. Ordinary calls
  and import filtering keep their existing meaning.
- A lambda default expression belongs to the enclosing scope. A walrus assignment
  there invalidates the affected outer binding; it cannot leave a false call edge
  to the original declaration. Parameters and the lambda body remain local. Nested
  lambdas and lexical private-name context retain their distinct scopes. Lambda
  body call inference is still unsupported.
- A class-body `__annotations__()` collision with that class's annotated assignments
  is explicitly unresolved when the Python version is unknown. The analyzer does
  not guess a Python target version. Annotations nested only inside a function or
  another class do not affect the enclosing class; methods still skip its namespace.
  The conservative choice follows the difference between
  [Python 3.13 annotated assignments](https://docs.python.org/3.13/reference/simple_stmts.html#annotated-assignment-statements)
  and [Python 3.14 deferred annotations](https://docs.python.org/3.14/whatsnew/3.14.html#pep-649-pep-749-deferred-evaluation-of-annotations).
- PR #17 supplies lexical private-name identities for supported bindings and simple
  module imports, preserving raw spelling, source IDs, hashes and ranges. Its
  generic-header and long-private-name limits remain; see the
  [reviewed contract](../reviews/2026-11-03-python-identity-and-ui-plan.md).

No new parser, dependency, interpreter, target configuration or migration is added.
The installer and live-index lifecycle are unchanged. Source is read without
execution. Dynamic/member/imported calls, runtime import paths and complete Python
semantics remain outside scope. `current` and preflight success describe bounded
freshness, not semantic correctness, runtime execution or test coverage.

## Rollback

Use the [documented update procedure](../../README.md#update-from-an-older-version)
with the original published **1.3.0** archive. Stop the owned foreground view, save
the owner's map outside the project, uninstall through its installed CLI and inspect
the result. Park retained remnants outside the scanned source tree; preserve edited,
unknown and recovery files. Install the verified older release and restore the map,
then inspect status/context and reload host instructions. Old binding receipts must
be rejected after either direction of the transition.

- 1.3.0 archive SHA-256: `13b6ac2d543f3f9bd66f2758f42b68102e5de9821281a2659a74f3576e65b14d`.
- 1.3.0 runtime digest: `d13a4194f38df22a266687d9b986e17c660ca824e61ec1437fe5e7623919f258`.

Rollback restores the known dependency-map defects as well as the previous version;
it is a recovery route, not a correctness improvement. Reverting source commits
does not change an installed target. Publication and real-target upgrades require
their own owner authority.
