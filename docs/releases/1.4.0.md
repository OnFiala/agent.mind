November 15 CORE/UI repairs. It adds no new parser or runtime dependency.

## Compatibility and installation

The archive is `agent-mind-1.4.0.tar.gz`, containing `agent-mind-1.4.0/` and the
same explicit runtime allowlist. Package and lockfile identify 1.4.0; dependency
pins, manifest schema and managed descriptor schema remain unchanged. Documentation
outside the payload is linked to immutable public source snapshots, not copied
from a maintainer workspace. Internet access is needed to open those links;
indexing and installed CLI operations remain local.

This is not an in-place update. Existing installations stay pinned. Use the
current installation's CLI to inspect status, save its user-owned map and uninstall;
park retained integration/recovery data outside the project before installing a
verified candidate with its exact digest. Restore only the saved naming map and
retain both parked copies. Follow the [installation guide](../../README.md#update-from-an-older-version).
Do not purge, overwrite edited instructions, copy this repository's naming map,
or execute scanned project code to discover its structure.

Accessor IDs and descendant IDs intentionally change in 1.4.0. Old selectors only
alias a unique declaration. A getter/setter pair is ambiguous under its old shared
selector and needs an explicit new selector; diagnostics retain candidates.
Never rewrite or delete user maps automatically. Positions tied to replaced IDs
may need to be arranged again. Older runtimes cannot resolve new-ID map entries.
See the [R10 contract](../reviews/2026-11-16-r10-accessor-identities.md).

## Rollback and remaining limits

Before merge, withdraw this PR. After merge, a source rollback requires a separately
authorized, reviewed revert of PR #34's merge commit, whose identity is recorded in
the PR. That restores the preparation base, including its already merged R01–R10
repairs; it does not restore published 1.3.1 runtime bytes or installed targets.
Published 1.3.1 and every installed target remain unchanged by this merge.
After a later authorized publication, a target rollback uses its
currently installed CLI, an outside-project backup of retained integration data,
and the exact old published release. Preserve source, maps, owner instructions,
unknown/edited files and recovery snapshots. Old revision/binding receipts expire.
A Git revert is separate from an installed-target rollback and restores no target
files by itself.
