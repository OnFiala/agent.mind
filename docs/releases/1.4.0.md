## Included scope

This minor version collects the already merged R01–R10 work and the four
November 15 CORE/UI repairs. It adds no new parser or runtime dependency.

- R01 fixes locale-dependent schema-1 artifact digest ordering.
- R02/R03 add the opt-in bounded agent context and concise preflight receipt,
  with revision/binding-bound retrieval of omitted evidence. Full JSON remains
  the default; output budgets do not promise indexing-time or memory savings.

  CommonJS resolution or Python source-root inference.

  Unrelated IDs stay stable; old accessor selectors resolve only uniquely.
- CORE/UI repairs preserve conservative HTTP evidence after captured writes,
  handle the exact inventory limit, and keep symbol/file selection consistent.
- This preparation reconciles the remaining roadmap, fixes bundle-facing
  documentation links, checks them against real package output and selects 1.4.0.

[ROADMAP](../../ROADMAP.md) owns current scope and the remaining R11/R12 steps,

## Compatibility and installation

The archive is `agent-mind-1.4.0.tar.gz`, containing `agent-mind-1.4.0/` and the
same explicit runtime allowlist. Package and lockfile identify 1.4.0; dependency
pins, manifest schema and managed descriptor schema remain unchanged. Documentation
outside the payload is linked to immutable public source snapshots, not copied
from a maintainer workspace. Internet access is needed to open those links;
indexing and installed CLI operations remain local.

This is not an in-place update. Existing installations stay pinned. Use the
current installation's CLI to inspect status, save its user-owned map and uninstall;
park retained integration/recovery data outside the project before installing a
verified release with its exact digest. Restore only the saved naming map and
retain both parked copies. Follow the [installation guide](../../README.md#update-from-an-older-version).
Do not purge, overwrite edited instructions, copy this repository's naming map,
or execute scanned project code to discover its structure.

Accessor IDs and descendant IDs intentionally change in 1.4.0. Old selectors only
alias a unique declaration. A getter/setter pair is ambiguous under its old shared
selector and needs an explicit new selector; diagnostics retain candidates.
Never rewrite or delete user maps automatically. Positions tied to replaced IDs
may need to be arranged again. Older runtimes cannot resolve new-ID map entries.
See the [R10 contract](../reviews/2026-11-16-r10-accessor-identities.md).

## Rollback and remaining limits

A source rollback requires a separately authorized, reviewed revert of PR #34's
merge `cb217aa684efda13274c773f1e962e291106ba0c`. That restores the preparation
base, including its already merged R01–R10 repairs; it does not restore published
1.3.1 runtime bytes or installed targets. Published 1.3.1 remains available.
Do not replace the published 1.4.0 assets or move its tag to perform a rollback.
If withdrawal is needed, separately authorize marking the release withdrawn and
changing latest-release guidance; preserve the recorded bytes and checksums.

An authorized target rollback uses its currently installed CLI, an outside-project
backup of retained integration data, and the exact old published release. Preserve
source, maps, owner instructions, unknown/edited files and recovery snapshots.
Old revision/binding receipts expire. A Git revert is separate from an
installed-target rollback and restores no target files by itself. No real-target
upgrade or rollback was performed for this publication.
